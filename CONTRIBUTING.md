# Contribuindo

## Fluxo recomendado

1. Defina a pergunta, problema ou decisão.
2. Pesquise conteúdo e ADRs existentes.
3. Classifique o artefato.
4. Crie uma branch curta.
5. Registre evidências, limitações e relações.
6. Valide Markdown, links e consistência arquitetural.

## Convenções

- Prefira mudanças pequenas e revisáveis.
- Use links relativos para conteúdo interno.
- Não reescreva ADR aceita para representar nova decisão.
- Não apresente resultados experimentais como padrões adotados.
- Use nomes em kebab-case para arquivos novos.
- Registre datas no formato `YYYY-MM-DD`.

## Commits

Use Conventional Commits quando fizer sentido, por exemplo:

```text
docs: add agent identity study note
feat: add ADR index validator
ci: add link checking workflow
```
